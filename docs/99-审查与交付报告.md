## 二、核心结论

**算法与代码层：未发现真实 bug。** 系统架构清晰（六层单向数据流、UI 与算法完全解耦），状态机用「合法迁移表 + guard」显式化，滑动窗口按真实时间加权（PERCLOS 不再用帧近似），双通道融合（几何 EAR + 语义 eyeBlink）配合质量门控有效抑制姿态假阳性，200+ 单元/回归断言覆盖关键路径。

**所有已发现并修复的问题，均为文档/文案与实际实现的不一致**（详见第三节）。这类问题对答辩与评审尤具风险——老师若按首页"8 秒校准"提问，而实际是 5 秒，会显得项目粗糙。本次已全部对齐。

## 三、本次修复清单（共 7 项）

### 修复 1：首页"8 秒基线校准"与实现不一致 ⭐ 高风险
**问题：** `web/index.html` 共 **4 处**写"8 秒校准/8 秒基线校准"，但 `config.js` 的 `calibration.durationSec = 5`（代码真实行为），README 也写 5 秒。首页文案构成**用户可见的虚假宣传**。  
**影响面：** 285 / 336 / 416 / 530 行（导航 title、开始按钮 title、特性卡片标题、收尾 CTA 副文案）。  
**修复：** 4 处统一改为"5 秒"。修复后全文检索 `web/` 下"8 秒"为零命中。

### 修复 2：README 实验数据指向过时 R4 结果
**问题：** `README.md:142` 写"四轮优化历程与最终指标（灵敏度 **86.4%** /特异度 100%）"，而最终版 `docs-evidence/准确率评估报告.md` 的 R5 结论已是 **92.6%**。86.4% 是 R4 旧数据。  
**修复：** 改为"六轮优化（R1–R5）与最终指标（灵敏度 92.6%/特异度 100%）"。

### 修复 3：README 实验数据表路径缺少 `figures/` 目录
**问题：** README 第 187–196 行的数据/图表表将文件写作 `accuracy-summary.csv` 等，但实际文件均在 `docs-evidence/figures/`。第 183 行与第 145 行已明示该目录，单文件名会让复现者找不到文件。同时"敏感性曲线"列还未改前缀而其他列已改，需统一。  
**修复：** 该表所有 CSV/SVG 路径统一加 `figures/` 前缀。

### 修复 4：README 导言"五类特征"与"七类"不一致
**问题：** 摘要写"融合 PERCLOS、眨眼动力学、哈欠、点头与头部姿态**五类**面部特征"，但 fusion.js 实际定义 **7 个权重**（perclos / closureDur / blinkRate / blinkDur / yawn / nod / headDev），且首页已正确写"七类特征"。README 导言是评审第一眼看到的摘要。  
**修复：** 改为"PERCLOS、闭眼时长、眨眼频率与时长、哈欠、点头、视线偏离**七类**面部特征"，与代码权重 key 与首页完全对齐。

### 修复 5：CHANGELOG 引用不存在的目录
**问题：** `docs/CHANGELOG.md:4` 写"每一项均可在 `system-delivery/comparison/文件变更清单.md` 中找到"，但 `system-delivery/` 目录在本仓库中**不存在**。  
**修复：** 改为仅引用真实存在的 `docs/代码审计报告.md`。

### 修复 6：tsconfig 引用不存在的类型目录
**问题：** `tsconfig.json` 的 `include` 含 `web/js/types/**/*.d.ts`，但该目录不存在；真实的 TypeScript 类型声明位于 `web/vendor/tasks-vision/vision.d.ts`。  
**修复：** include 改为 `web/vendor/tasks-vision/*.d.ts`（覆盖实际存在的 vision.d.ts）。

### 修复 7：交付说明与 gen-y4m 注释的过时数据
**问题①：** `交付说明.txt` 仍保留 R4 旧数据——回归 138 项（实际 195）、灵敏度 86.4%（实际 92.6%）、F1 0.927（实际 0.962）、MCC 0.702（实际 0.811）、检出延迟均值 15.3s（实际 8.68s）。  
**问题②：** `tools/gen-y4m.mjs:26` 注释写"8 秒校准/有效样本≥60"，与 5 秒/≥30 的真实配置不符。  
**修复：** 交付说明更新为 R5 终版数值；gen-y4m 注释同步修正。

> **保留合理的"8 秒"引用：** `docs/技术文档.md`（criticalClosureMs×0.6=1.08 秒等算法参数）、`docs/第四轮任务台账.md` 与 `第四轮优化提示词.md`（历史优化记录，记载"当时修了 8 秒校准混淆问题"，属于**历史事实记录**）、`docs/真人实测问题汇总.md`（头部后仰"保持 8 秒"为实测步骤）、`web/js/ui/report.js`（危险闭眼阈值 1.8 秒说明）——这些"8 秒"与"基线校准时长"是两回事，语义合理，**未做修改**。
