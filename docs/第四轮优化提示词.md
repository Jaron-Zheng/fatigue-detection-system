# 驾驶员疲劳检测系统 · 第四轮优化任务书

**多角色循环审视 · 体验与质量纵深 · 每项结论必须有实证**

## 一、你将接手的是什么

一个已通过三轮优化的本科毕业设计：Web 端驾驶员疲劳检测系统。
第三轮终点（git tag `v3.0.0`）之后，工作区又沉淀了一轮**未入库**的
Tesla 风格 UI 重设计与真人反馈修复（`docs/CHANGELOG.md` 3.0.0 / 3.1.0）。
本轮开始前已将其验证（full-verify 全绿）并固化为基线
**`v4.0.0-baseline`（commit 33d3fd9）**。

## 二、第四轮的目标

前三轮解决了"能跑、安全、有测试、工程成熟、答辩可支撑"。第四轮解决的是：

1. **体验纵深**——用苛刻的、真实的多角色眼光（美学、产品、新手、信息设计、
   无障碍、危机场景）把"看起来不错"逼到"经得起盯着看"。
2. **质量纵深**——对未提交过的 Tesla 重设计做一次真正的工程级审视
   （它从未经过第三轮那种逐角色验收）。
3. **循环机制**——角色审视 → 执行 → 验证 → 再审视，至少两轮循环，
   每轮循环的角色粒度比上一轮更细。

## 三、执行纪律（继承前三轮，全部有效）

1. **算法参数零改动**：config.js / fusion.js / indicators.js 等疲劳判定
   数值不动，除非复现出有完整证据链（现象→复现→根因→修复→前后对比）
   的真实缺陷。
2. **不虚构**：任何"已完成"必须附真实命令输出片段；无证据视为未完成。
3. **不放水**：不允许为让测试通过而删改断言。
4. **每批次一次 commit**：消息含关键实测数字。
5. **优先级裁决**：正确性 > 不破坏现有测试 > 可维护性 > 性能 > 视觉与体验。

## 四、角色编排

### 批次一 · 体验层（审视 → 执行）
| 角色 | 审视重点 |
|---|---|
| 苛刻的美学总监 | 文字排版（字号阶/行高/字重/字距/标点悬挂）、留白节奏、色彩纪律、圆角与描边一致性、图标对齐 |
| 产品经理 | 功能取舍质疑：什么该删、什么缺失、认知负担、信息架构、演示链路 |
| 首次使用的新手司机 | 首屏 5 秒能否看懂、校准 8 秒的引导、报警时能否立刻明白该做什么 |
| 信息设计师（数据可视化） | 指标卡语义、趋势图可读性、报告页信息层级、数字格式与单位 |

### 批次二 · 工程层（审视 → 执行）
| 角色 | 审视重点 |
|---|---|
| 资深前端架构师 | Tesla 重设计的 CSS/HTML 结构质量、模块边界、死代码、可维护性 |
| 性能工程师 | 首屏加载、运行时开销、长任务、内存 |
| 安全研究员 | 超出现有 41 项集成测试的攻击面 |
| 测试工程师 | 测试盲区、断言强度、工具健壮性（如 screenshot.mjs 不校验页面加载） |

### 批次三 · 学术与交付层（审视 → 执行）
| 角色 | 审视重点 |
|---|---|
| 答辩评委 | 一眼能看到什么、会被问倒什么、演示风险 |
| 文档工程师 | 26 份文档的一致性、时效性、互相引用正确性（设计语言已 Apple→Tesla，文档跟上了吗） |
| 无障碍与适老化专家 | 老年驾驶员视角：字号、对比度、操作复杂度、语音 |
| 隐私合规 | 个人信息保护口径、数据导出的合规说明 |

### 循环二 · 深度细化（更细粒度角色）
字距与微交互设计师 / 危机场景用户（报警瞬间） / 极端环境用户（逆光/戴镜/夜间） /
运维交付视角（交付包完整性）等——由循环一的结果决定具体编排。

### 终验角色
独立复核全部"已完成"声明（重跑测试、抽查代码、比对截图），产出
《第四轮交付报告.md》，更新《第四轮任务台账.md》。
