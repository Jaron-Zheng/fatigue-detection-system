## 二、复跑中发现并修复的问题（本报告的核心增量）

### 1. CSP 拦截内联兼容性检测脚本（产品缺陷，已修复）

- **现象**：混沌测试 20 个场景全部失败，每个场景捕获同一条控制台错误——
  `Executing inline script violates the following Content Security Policy directive "script-src 'self' 'wasm-unsafe-eval'"`。
- **根因**：2026-08-30 GitHub Pages 部署修复时在 `index.html` 加入内联的浏览器
  兼容性检测脚本；线上（gh-pages）不下发 CSP 头所以正常，本地服务器 CSP
  无 `unsafe-inline`，脚本被拦截——本地环境下该检测形同虚设，且每次页面
  加载产生一条 CSP 违规，污染所有监控控制台的浏览器测试。
- **修复**：内联脚本抽为外部脚本 `web/js/compat.js`（CSP 允许同源脚本），
  语义不变。修复后混沌测试 20/20 恢复。

### 2. 兼容性检测硬阻断误杀演示模式（产品缺陷，已修复）

- **现象**：跨内核测试 WebKit 侧"应用未启动"。探针证实无头 WebKit 无
  getUserMedia，检测把整页替换为"浏览器兼容性不足"错误页。
- **根因**：该检测对 WebAssembly / getUserMedia / WebGL2 三项缺失一律整页
  阻断。但产品本身有优雅降级链路（preflight.js：无摄像头 → 实时模式不可用、
  演示模式不受影响；无 WebGL2 → 回退 CPU 委托），硬阻断与降级设计冲突。
  此缺陷长期潜伏——本地 CSP 拦截使该脚本从未真正执行，抽为外部脚本后
  首次运行即暴露。
- **修复**：硬阻断仅保留"无 WebAssembly"（浏览器太老，系统完全无法运行）；
  摄像头与 WebGL2 缺失交由 preflight 在启动检测时给出降级提示。修复后
  WebKit 12/12 恢复。

### 3. 键盘测试可见性过滤器误判抽屉控件（测试口径缺陷，已修复）

- **现象**：键盘专项 Tab 遍历断言失败——"Tab 只到达 12/23，存在键盘不可达
  元素"。
- **根因**：设置抽屉关闭态使用 `visibility:hidden`（为滑出动画保留布局，
  浏览器 Tab 语义正确跳过），但测试的可见性过滤器只检查 `offsetParent`
  （对 visibility:hidden 元素仍非 null），把抽屉内 11 个控件误计入分母。
  探针证实 Tab 实际顺序完整覆盖页面全部 12 个可达元素后回到 body。
- **修复**：`tools/keyboard-test.mjs` 过滤器改用 `checkVisibility({checkVisibilityCSS:true})`
  按浏览器 Tab 语义判断可见性。修复后 9/9 恢复。
