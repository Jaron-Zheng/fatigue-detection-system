# 算法变更说明

## 结论（先说最重要的）

**本轮优化没有修改任何疲劳判定算法。**
隶属函数转折点、融合权重、EMA 系数、等级阈值、滞回带宽、驻留时间、
各事件判定阈值——全部与基线快照（`system-delivery/original/system/web/js/config.js`）
逐行比对一致。这是刻意为之：提示词要求「不得通过调参制造更准确的假象」，
且算法层的既有行为已被真人实测与回归测试锚定，无理由扰动。

## 与算法间接相关的改动

### 1. 本地配置合并加固（web/js/config.js）

- **修改前**：`loadUserConfig()` 将 localStorage 中的 JSON 直接
  `deepMerge` 进 CONFIG，仅判断 `k in target`。损坏或恶意构造的
  本地配置（如把 `perclosSec` 改成字符串）会原样写入，
  使窗口计算产生 NaN，表现为疲劳指数恒为 NaN 或等级卡死。
- **修改后**：数字字段只接受有限数值；`__proto__` /
  `constructor` / `prototype` 键被忽略；patch 非纯对象时整体放弃。
- **是否影响结果**：不影响。合法配置（类型正确的用户调节值）
  行为与之前完全一致；只是非法输入从「污染参数」变为「被忽略」。
- **回归测试**：`[1.1] 本地配置安全合并` 4 条断言；
  既有 `[2]~[7]` 全部算法链路断言在修改后仍全部通过（31/31），
  证明算法行为无漂移。

### 2. 视频离线评测输入校验（web/js/core/video-source.js）

- **修改前**：任意文件直接进入 blob 解码；
- **修改后**：空文件 / 超 1GB / 非 video MIME 拒绝。
- **是否影响结果**：不影响评测算法本身。评测仍使用与实时检测
  同一套管线、固定步长，结果与主机性能无关的性质不变。

### 3. 其余 UI / 安全改动

均不接触算法数据链路（特征层 → 指标层 → 融合层 → 记录层）。

## 基线算法的可追溯性（本轮审查确认）

以下关键参数的取值依据全部保留在代码注释与 `docs/技术文档.md` 中：

| 参数 | 值 | 依据位置 |
|---|---|---|
| PERCLOS 隶属区间 | 6% → 32% | fusion.js 注释（清醒基线实测 2%~5%） |
| 闭眼判定 | 闭合度 ≥0.80 进 / ≤0.60 出 | indicators.js（P80 定义 + 滞回） |
| 融合式 | 0.6·geo + 0.4·sem | indicators.js（真人实测姿态假阳性记录） |
| 语义否决阈值 | 0.40 | config.js（单被试实测分离区间 0.427~0.613 的中点附近） |
| 危险闭眼 | 1.8s 重度 / 0.6 倍中度 | fusion.js override |
| 等级防抖 | 滞回 + 驻留 + 逐级 + 最短保持 | fusion.js `_applyHysteresis` |

## 已知限制（未变）

1. EAR 对仰角敏感（由语义通道与质量门控补偿，见技术文档）；
2. 参数为单被试标定值，跨人群适用性未验证；
3. 准确率未经规模化数据集验证——视频评测工具就绪，等待多被试标注。
