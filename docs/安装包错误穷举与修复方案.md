# 穷举：用户安装运行疲劳检测系统的所有潜在错误与修复方案

## 一、安装阶段错误（用户双击安装程序后）

### E-01 安装路径包含特殊字符导致启动失败
- **现象**：安装到含 `#`、`&`、`+` 等特殊字符的路径后，启动器 exe 无法找到 server.js
- **根因**：SEA launcher 用 `process.execPath` 获取路径，路径中特殊字符不影响文件系统，但可能影响子进程的 `PATH` 环境变量
- **修复**：确保 `sea-launcher.js` 中所有路径都用 `path.join`（已正确），不传 `PATH` 环境变量

### E-02 杀毒软件拦截 SEA exe
- **现象**：杀毒软件可能将 SEA 注入的 exe 误判为可疑文件并拦截
- **根因**：SEA 修改了 node.exe 的数字签名，杀软可能不信任
- **修复**：在许可协议中注明"如遇杀软拦截请添加信任"（已在 LICENSE.txt 中）

### E-03 360安全卫士/火绒拦截端口监听
- **现象**：安装后启动时，360等安全软件弹窗提示"程序试图监听端口"
- **根因**：server.js 监听 127.0.0.1:5180，安全软件可能拦截
- **修复**：在启动横幅中提示"如遇安全软件拦截请选择允许"

### E-04 安装到中文路径导致 WASM 加载失败
- **现象**：安装到 `D:\我的软件\疲劳检测系统\` 后，MediaPipe WASM 模块加载失败
- **根因**：WASM 的 `FilesetResolver.forVisionTasks()` 内部用 fetch 加载 wasm 文件，部分浏览器对中文路径的 URL 编码处理可能有问题
- **修复**：在安装脚本中默认安装路径不含中文（但用户可自行修改）

## 二、启动阶段错误（用户点击快捷方式后）

### E-05 端口被占用导致启动失败
- **现象**：用户电脑上已有其他程序使用 5180 端口
- **根因**：server.js 已有端口自选机制（最多尝试 20 个端口），但若全部被占用会退出
- **当前处理**：已实现端口递增尝试 ✓
- **改进**：launcher.exe 应在启动失败时显示错误信息并保持窗口打开（已实现 `process.stdin` 等待按键）

### E-06 浏览器未自动打开
- **现象**：服务器启动成功但浏览器没有自动打开
- **根因**：`server.js` 用 `cmd /c start "" url` 打开浏览器，某些情况下可能失败
- **当前处理**：已有 try-catch 兜底，不会崩服务 ✓
- **改进**：在控制台显示访问地址，让用户手动复制

### E-07 防火墙拦截
- **现象**：Windows 防火墙首次拦截 node.exe 的网络监听
- **根因**：SEA exe 首次监听端口时，Windows Defender 防火墙可能弹出确认
- **修复**：在启动提示中告知用户"如遇防火墙提示请选择允许访问"

## 三、浏览器运行阶段错误

### E-08 摄像头权限被拒绝
- **现象**：用户点击"开始检测"后，浏览器弹出权限请求，用户点了"拒绝"
- **当前处理**：`CameraSource.friendlyError()` 已提供详细错误信息 ✓
- **改进**：错误提示中增加操作截图引导

### E-09 摄像头被其他程序占用
- **现象**：Zoom、Teams、微信等会议软件正在使用摄像头
- **当前处理**：`friendlyError` 已处理 `NotReadableError` ✓

### E-10 摄像头权限超时
- **现象**：用户离开电脑，权限弹窗 15 秒未被处理
- **当前处理**：已实现 15 秒超时兜底 ✓

### E-11 WebAssembly 不支持
- **现象**：用户使用 IE 或非常旧的浏览器
- **当前处理**：`face-engine.js` 的 `_friendlyError` 已处理 ✓
- **改进**：在 index.html 中增加浏览器兼容性检测

### E-12 MediaPipe 模型加载失败
- **现象**：vendor 目录下的模型文件损坏或缺失
- **当前处理**：`launcher.js` 检查文件存在性 + `preflight.js` 探测可达性 ✓
- **改进**：增加文件完整性校验（文件大小比对）

### E-13 GPU 推理失败回退 CPU
- **现象**：WebGL2 不可用或 GPU 驱动有问题
- **当前处理**：`face-engine.js` 已实现 GPU→CPU 自动回退 ✓

### E-14 localStorage 被禁用
- **现象**：用户在浏览器设置中禁用了 cookie/存储
- **当前处理**：`preflight.js` 检测到并降级为"仅本次会话有效" ✓

### E-15 AudioContext 被浏览器自动播放策略阻止
- **现象**：疲劳报警时没有声音
- **当前处理**：`alarm.js` 在用户首次交互后创建 AudioContext ✓
- **改进**：增加视觉报警兜底（已有闪屏 ✓）

### E-16 浏览器关闭后服务未停止
- **现象**：用户关闭浏览器标签页后，launcher.exe 的控制台窗口仍然开着
- **当前处理**：这是设计行为（关闭控制台窗口才停服务）✓
- **改进**：在控制台提示中说明"关闭此窗口即停止服务"

## 四、检测过程中的错误

### E-17 人脸丢失后无法恢复
- **现象**：用户短暂离开画面后回来，系统不恢复检测
- **当前处理**：`quality.js` 有质量门控，`render-loop.js` 会自动重试 ✓

### E-18 光照不足导致检测异常
- **现象**：光线很暗，EAR 值不稳定
- **当前处理**：`quality.js` 的 `LightingMonitor` 检测并提示 ✓

### E-19 检测过程中浏览器崩溃
- **现象**：长时间运行后浏览器标签页崩溃（OOM）
- **当前处理**：`recorder.js` 定期采样不会无限增长内存 ✓
- **改进**：增加长时运行的内存监控提示

### E-20 导出报告时下载失败
- **现象**：用户点击"下载报告"但没有反应
- **当前处理**：`export-report.js` 使用 `URL.createObjectURL` + `<a download>` ✓
- **改进**：增加导出失败的 toast 提示

## 五、安装/卸载阶段错误

### E-21 卸载后残留文件
- **现象**：卸载后安装目录仍有文件
- **当前处理**：`[UninstallDelete]` 已配置 `filesandordirs` 清理整个目录 ✓

### E-22 重复安装覆盖旧版本
- **现象**：用户在旧版本基础上安装新版本
- **当前处理**：Inno Setup 默认覆盖安装 ✓

### E-23 安装程序自身被拦截
- **现象**：SmartScreen 或杀软拦截未签名的安装程序
- **根因**：安装程序没有数字签名
- **修复**：在 README 或下载页面说明"如遇 SmartScreen 拦截请点击'仍要运行'"

## 六、需要修复的优先级

### 高优先级（影响用户体验）
1. **E-03** 安全软件拦截端口 → 在启动横幅增加提示
2. **E-07** 防火墙拦截 → 在启动横幅增加提示
3. **E-12** 模型文件完整性 → 增加文件大小校验

### 中优先级（影响特定场景）
4. **E-11** 浏览器兼容性 → 增加 `<noscript>` 和兼容性检测
5. **E-20** 导出失败提示 → 增加 try-catch + toast

### 低优先级（已有兜底，仅需完善）
6. **E-05** 端口占满 → 增加更友好的错误信息
7. **E-19** 内存监控 → 长时运行提示
