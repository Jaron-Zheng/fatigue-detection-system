# 启动故障排查

按「现象 → 原因 → 处理」组织。覆盖一键启动（.bat / .ps1）与手动启动两种方式。

## 1. Node.js 未安装

- **现象**：双击 `一键启动.bat` 显示 `[X] Node.js not found`。
- **处理**：到 https://nodejs.org 安装 LTS 版本（≥18），装完重新双击。
  安装时保持默认选项即可，无需安装任何全局 npm 包。

## 2. Node.js 版本过低

- **现象**：启动器显示「Node.js 18 或更高版本是必需的，当前为 vXX」。
- **处理**：升级到 LTS。若机器上有多个 Node 版本（nvm 等），
  确认当前 shell 的 `node -v` ≥ v18。

## 3. 端口被占用

- **现象**：提示「端口 5180 被占用，尝试 5181 ...」。
- **说明**：这是正常容错，服务器会自动向后尝试最多 20 个端口，
  成功后打印的「访问地址」才是真实地址。
- **手动指定**：`node server/server.js --port 6000`（或 PowerShell：
  `.\一键启动.ps1 -Port 6000`）。非法端口会得到中文报错并退出。

## 4. 启动脚本乱码

- **现象**：.bat 窗口出现奇怪字符或命令截断。
- **说明**：本项目 .bat 刻意保持纯 ASCII（中文提示全部由
  `tools/launch.js` 输出），正是为了避免 cmd 按 GBK 解析 UTF-8
  破坏语法的问题。若你编辑过 .bat 并加入中文，请改回 ASCII。
- **窗口字体**：若中文提示显示为方框，把控制台字体换成
  「Cascadia Mono」或新宋体即可，不影响运行。

## 5. 中文路径 / 带空格路径

- 已实测：项目放在含中文的目录（如 `桌面\第二版`）可正常启动。
- 脚本用 `cd /d "%~dp0"` 与 Node 的 `__dirname` 定位，
  与盘符、空格、中文均无关。不要依赖旧版 cmd 的 8.3 短路径。

## 6. 浏览器没有自动打开

- **现象**：窗口显示「访问地址 : http://127.0.0.1:5180/」但浏览器未弹出。
- **处理**：手动在浏览器输入该地址即可。服务已正常运行。
- **说明**：个别企业环境禁用了 `cmd /c start` 关联；不影响功能。

## 7. 摄像头权限

- **现象**：页面提示需要摄像头，或点击开始检测后无画面。
- **原因**：浏览器只在安全上下文（localhost / HTTPS）询问摄像头权限。
- **处理**：务必使用启动器给出的 `http://127.0.0.1:端口` 访问，
  不要用 `file://` 双击 index.html，也不要用局域网 IP 访问；
  在浏览器地址栏左侧「站点信息」中把摄像头设为允许。

## 8. 模型资源缺失

- **现象**：启动横幅显示「以下本地推理资源缺失」。
- **处理**：启动器首次运行会自动下载（约 26MB）；失败时手动执行
  `node tools/fetch-vendor.js`。下载完成后系统完全离线可用。

## 9. WASM 加载失败

- **现象**：控制台报 wasm 编译错误。
- **处理**：确认通过本地服务器访问（MIME `application/wasm` 依赖服务器）；
  GPU 初始化失败时系统会自动回退 CPU（页面提示委托方式），无需手动处理。

## 10. 浏览器兼容

- 支持：Chrome / Edge 等现代 Chromium 内核浏览器（WebGL + WASM）。
- Firefox：代码未使用 Chrome 专有 API，理论可用，但本项目未在
  Firefox 实测（环境限制），遇到问题优先换 Chromium。
- Safari：未验证，不建议作为答辩环境。

## 11. 防火墙拦截

- 服务器只监听 `127.0.0.1`，不暴露到网络，一般不触发防火墙弹窗。
- 若安全软件询问，选择允许（仅本机回环通信）。

## 12. 页面空白 / 控制台错误

- 先确认地址是启动器打印的那一个（端口可能因占用而后移）；
- 打开开发者工具（F12）看 Console：缺少静态资源会给出 404 文件名；
- 若改过代码，服务器对源码使用 `no-store`，刷新即生效，无需重启；
  vendor 资源有 24h 缓存，极端情况下换用无痕窗口排除缓存问题。

## 13. 关闭窗口后服务未退出

- 关闭启动窗口即终止服务（Node 进程随窗口结束）。
- 若用 `npm start` 在终端启动，按 Ctrl+C 停止。

## 14. 拿到的是 git 仓库而不是压缩包：如何查看历史版本

第三轮起交付改用 git 仓库（不再手工复制整份文件夹）。常用操作：

```powershell
# 查看演进历史（每个角色一个提交）与版本标签
git log --oneline
git tag -l            # v2.0.0-audited = 第二轮审计基线；v3.0.0 = 第三轮交付

# 只读地看某个历史版本（detached HEAD，不影响当前工作）
git checkout v2.0.0-audited
# 看完回到最新状态
git checkout main

# 只想看某个历史版本里的单个文件（不切整个工作区）
git show v2.0.0-audited:web/js/config.js

# 两个版本之间的变更清单
git diff v2.0.0-audited v3.0.0 --stat
```

注意：`original/system/web/vendor/` 的大文件在第三轮已去重（见该目录 README.md），
checkout 到历史版本时 git 会从仓库对象里完整还原，无需联网。
