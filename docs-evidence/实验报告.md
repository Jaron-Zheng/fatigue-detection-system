## 1. 判别有效性（Q1）

- 混淆矩阵口径：二分类（轻度及以上 = 疲劳），按采样点计数与时间加权双口径
  （等间隔采样下两口径数值一致）。工作点指标：灵敏度 92.6%、特异度 100%、
  F1 0.962、MCC 0.811、平衡准确率 96.3%。
- ROC/PR 由 `web/js/core/evaluation.js` 的 `computeRocPr` 计算：
  疲劳指数 0–100 以 1 分步长扫描 101 个工作点，AUC 为经验 ROC 梯形积分
  （与配对法 Mann-Whitney U 恒等，平局记 0.5，回归测试 7.1 已交叉验证）。
- 评估结果（43,650 采样点，正例 36,970 / 负例 6,680）：
  **AUC = 0.99973，AP = 0.99992**。
- 论文写法建议：以 AUC/AP 报告判别力，以混淆矩阵报告工作点指标，
  并注明二分类映射与计数口径；真实数据口径见第 8 节，两者结论方向一致。

## 2. 基线对照（Q2）

- 基线：单一 PERCLOS 阈值（文献常用 0.05–0.20 区间扫描），与融合系统同一数据、
  同一口径（按采样点计数；PERCLOS 未就绪帧按清醒处理）。
- 评估结果（baseline-comparison.csv）：

| 方法 | 灵敏度 | 特异度 | F1 | MCC |
|------|--------|--------|----|-----|
| PERCLOS ≥ 0.05 | 93.7% | 100% | 0.968 | 0.825 |
| PERCLOS ≥ 0.08 | 87.8% | 100% | 0.935 | 0.711 |
| PERCLOS ≥ 0.10 | 82.1% | 100% | 0.902 | 0.627 |
| PERCLOS ≥ 0.12 | 72.4% | 100% | 0.840 | 0.513 |
| PERCLOS ≥ 0.15 | 58.1% | 100% | 0.735 | 0.409 |
| 七特征融合（内置分界） | 92.6% | 100% | 0.962 | 0.811 |

- 诚实结论：在合成评估数据上，宽松的瞬时 PERCLOS 阈值（≥0.05）F1 高于融合系统。
  原因有二：① 合成剧本的疲劳段 PERCLOS 信号极强且干净，
  单特征即可线性分离；② 融合系统带等级驻留防抖（dwell 600ms +
  minHold 轻度 1s / 中度 2.5s / 重度 6s）与 EMA 平滑，响应更保守——
  这是抑制等级抖动的工程代价。
- 论文写法建议：从两个角度论证融合价值：
  (a) 鲁棒性——对抗场景实验（第 5 节）显示单特征污染时融合零误报，
  PERCLOS 基线在墨镜/揉眼场景无解；(b) 等级输出——基线只有二分类，
  融合可输出四级分级与归因，这是报警分级的前提能力。

## 3. 权重消融（Q3）

- 口径：贡献扣除——将该指标隶属度置 0、其余权重不变，观察平均疲劳指数与
  疲劳时间占比的变化（变化越大越依赖该特征）。
- 结果（完整模型基线：平均指数 48.50，疲劳占比 0.7686）：
  PERCLOS −12.89（#2）、最长闭眼 −11.27（#3）、哈欠频率 −15.31（#1）、
  点头频率 −3.61（#4）、眨眼频率 −1.27（#5）、眨眼时长 −0.34（#6）、
  注意力分散 0（#7）；哈欠频率对疲劳占比影响最大（−0.231）。
- 复现：`node tools/accuracy-eval.mjs`（第三节），界面入口为
  设置抽屉"运行权重消融实验"。
- 论文写法建议：按贡献度排序逐特征讨论，并与权重配置
  （config.js fusion.weights，PERCLOS 0.34 / 最长闭眼 0.23 / 哈欠 0.21）
  互印证；哈欠频率权重经真实数据上调后成为消融贡献第一名（R5，
  见第 8 节），与 NTHU-DDD 数据集自身以哈欠行为区分困倦会话的设计一致。

## 4. 检出延迟（Q4）

- 口径：人工标注疲劳区间起始 → 系统首次判为"轻度及以上"的时差；
  漏检区间单列，不以 0 计入。
- 评估结果：10 个疲劳区间，检出 10、漏检 0，延迟均值 8.68s / 中位 6.63s，
  最快 2.2s（趋势加速器生效轮次），最慢 19.7s。
- 延迟来源分解（写论文时可直接引用 evaluation.js 注释）：
  PERCLOS 滑动窗口的固有累积 + EMA 平滑 + 等级驻留。属方法固有特性，
  通过安全兜底（持续闭眼 ≥1.8s 直接判重度，绕过平滑）缓解极端情况。
- 论文写法建议：报告均值/中位数/最大值三组数，并说明
  危险闭眼场景由 override 通道保证秒级响应，与指数通道的延迟分开讨论。

## 5. 对抗场景鲁棒性（Q5）

- 实验设定：合成"清醒驾驶员做出易致单一特征误判的非典型行为"的特征帧
  （低头 32° / 每 700ms 揉眼 / 快速说话 / 过减速带点头等，干扰模式按
  场景物理特征设计），指标流直接喂给真实 IndicatorEngine + FusionEngine，
  每场景 450 帧（≈15s，33ms 步长），全程计入统计。
- 结果（6/6 PASS，复现：`node tools/accuracy-eval.mjs` 第五节）：

| 场景 | 期望 | 结果 |
|------|------|------|
| 低头看手机（视线偏离 85%） | 保持清醒 | 清醒 450/450 帧，误报 0% |
| 频繁揉眼（PERCLOS 15%、眨眼变慢） | 保持清醒 | 清醒 450/450 帧，误报 0% |
| 说话（哈欠特征被污染 3 次/分） | 保持清醒 | 清醒 450/450 帧，误报 0% |
| 过减速带（点头特征被污染 6 次/分） | 保持清醒 | 清醒 450/450 帧，误报 0% |
| 戴墨镜（眼部不可靠） | 信号不可用 | 不可用 450/450 帧，无误报分 |
| 侧脸（人脸持续丢失 80%） | 信号不可用 | 不可用 450/450 帧，无误报分 |

- 论文写法建议：强调两点——① 单特征污染场景融合零误报
  （权重稀释 + 多信号互证）；② 测不准时输出"信号不可用"而非猜测分
  （虚假安全感比明确的不可用更危险）。

## 8. 真实标注数据评测与 R5 参数调优（Q8）

### 8.1 评测方法与数据

- 数据集（公开标注、本地推理，无任何上传）：
  - **NTHU-DDD**（NTHU Driver Drowsiness Detection，帧提取版）：
    4 被试 / 48 clips / 66,521 帧，每个行为片段含清醒会话与睡眠剥夺
    会话各一次录制（目录名即二分类标签 drowsy/notdrowsy）。
    时间尺度经生理锚点标定为 30fps（EAR 闭合段中位 6–7 帧 = 200–233ms
    正常眨眼时长；真实哈欠段 113–192 帧 = 3.8–6.4s 哈欠生理时长）。
  - **UTA-RLDD**（UTA Real-Life Drowsiness Dataset，帧抽样版）：
    60 被试 / 6,924 帧（alert/drowsy 独立帧，无时间连续性），
    用于帧级眼睛状态跨域验证。
- 评测链路：`realdata-collect.mjs` 在无头 Edge 中驱动与生产完全相同的
  FaceEngine → FeatureExtractor 推理（人脸检出率 99.1% / 95.5%），
  逐帧特征缓存后由 `realdata-eval.mjs` 在 Node 回放完整
  Calibrator → IndicatorEngine → FusionEngine 管线（推理一次、复用多次）。
- 判定口径：clip 级二分类（drowsy=正类）。个性化标定取该被试清醒片段
  前 5s（镜像生产流程：清醒上车→标定→状态演化）。主判定规则 ratio
  （疲劳帧占比 ≥ 30%）。
- 防过拟合纪律：被试级分组——调优集 001+002，测试集 005+006 封存，
  最终全量验证才合并。

### 8.2 真实数据基线（默认参数）与根因诊断

- **真实数据基线（R4 参数）：灵敏度 81.0% / 特异度 92.6% / F1 0.850 / MCC 0.746**
  ——对照模拟口径宣称的 86.4% / 100%，量化了模拟与真实的差距，
  也解释了真人使用时"有时不准"的观感。
- 误差归因（逐 clip 隶属度诊断，`realdata-diagnose.mjs`）抓到三个根因：
  1. **闭眼度阈值 0.8 过严**（原为 indicators.js 硬编码）：真实眨眼峰值
     闭合度 ≈ 0.78（几何通道饱和 1.0，语义通道受眼镜影响仅 ≈0.44），
     差 0.02 不过线 → 眨眼大面积漏检 → 眨眼率虚低 → 误触发
     "深度嗜睡低频眨眼"伪信号（同时制造漏检与误报）。
  2. **频率指标无就绪门控**：开局 1 次点头 ÷ 1s 观测 = 60 次/分的荒谬
     频率（PERCLOS 有 5s 门控，blinkRate 有 15s 门控，yawn/nod 漏配）。
  3. **哈欠单指标权重封顶 14 分**：纯哈欠片段（困倦会话的典型形态）
     永远达不到轻度阈值 24；且睡眠剥夺者的低幅哈欠 MAR 峰值
     与说话分布重叠，原阈值 0.35 增量下完全无法注册。

### 8.3 R5 参数调优（写回 config.js 的默认值）

| 参数 | 旧值 | 新值 | 依据（调优集扫描） |
|------|------|------|--------------------|
| event.eyeCloseOn（原硬编码） | 0.80 | **0.75** | 0.80→0.75：灵敏度 83.3→91.7%，特异度不变；0.70 特异度跌至 87.5% |
| calibration.marOpenDelta | 0.35 | **0.25** | 低幅哈欠可注册且特异度不降；≤0.20 会把说话判成哈欠（分布重叠点） |
| fusion.weights.yawn | 0.14 | **0.21** | 真实数据第一线索；纯哈欠片段 0.14 权重封顶 14 分无法触阈 |
| fusion.weights.nod / blinkRate | 0.10 / 0.10 | **0.08 / 0.08** | 点头阈值真实头部运动下过敏（清醒被试 95s 内 10 次伪触发）；blinkRate 依赖眨眼检出质量 |
| fusion.weights.blinkDur / headDev | 0.05 / 0.04 | **0.04 / 0.02** | 消融贡献最低档，释放权重给哈欠 |
| fusion.rateReadyMs（新增） | blinkRate 独享 15000 | **三项频率统一 15000** | 修复 yawn/nod 无门控的开局频率虚高 |
| event.eyeCloseOff（原硬编码） | 0.60 | **0.60（参数化）** | 阈值集中原则，值不变 |

### 8.4 调优结果

| 口径 | R4（旧参数） | R5（新参数） | 变化 |
|------|-------------|-------------|------|
| **真实数据全量**（48 clips，ratio） | 灵敏度 81.0% / 特异度 92.6% / MCC 0.746 | **灵敏度 85.7% / 特异度 92.6% / MCC 0.788** | +4.8pp / 持平 / +0.042 |
| 真实数据·无眼镜场景 | — | 灵敏度 100% / 特异度 91.7% / F1 0.947 | — |
| 真实数据·封存测试集（005+006） | 灵敏度 77.8% / 特异度 90.9% / MCC 0.698 | 灵敏度 77.8% / 特异度 90.9% / MCC 0.698 | 持平（误差性质改善：伪信号 FP 消除） |
| **模拟数据全量** | 灵敏度 86.4% / 特异度 100% / 延迟 15.3s | **灵敏度 92.6% / 特异度 100% / 延迟 8.7s** | +6.2pp / 持平 / −6.6s |
| UTA-RLDD 帧级 AUC（双通道融合） | — | **0.7178**（几何 0.7151 / 语义 0.7030） | 融合 > 单通道，双通道设计价值成立 |

- 剩余误差全部归因于三类硬边界（论文如实说明）：
  ① 低幅压抑型哈欠与说话的 MAR 分布重叠（不可分，需多模态）；
  ② 片段短于指标窗口（3.2s/6.4s clip vs 20s PERCLOS 窗口）；
  ③ 标注噪声（清醒标签片段内含 1.5–5s 真实闭眼，系统判定反而正确）。
- 调优后全量回归：check / 138 回归 / 41 集成 / 20 混沌 / typecheck / lint
  全部通过；对抗场景 6/6 保持零误报（揉眼场景融合闭合度峰值 0.64，
  低于新阈值 0.75，安全余量保留）。
