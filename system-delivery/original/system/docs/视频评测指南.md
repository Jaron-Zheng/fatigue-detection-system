# 视频离线评测指南

用于做**真人准确率验证**，把系统从"算法逻辑正确"推进到"检测有效"。
这是毕业设计答辩中最容易被追问的一环，也是论文实验章节的核心数据来源。

---

## 一、为什么必须自己标注

疲劳状态的"真实标签"只有两个有效来源：

1. **被试本人的主观自评**（学术上对应 KSS 嗜睡量表）
2. **生理信号金标准**（脑电 EEG，需要专业设备）

你就是被试，你知道每一段自己困不困，因此**你的自评就是最有说服力的标签**。

反过来，用任何算法（包括 AI 视觉模型）的判断当标签都不成立——
那是用一个未经验证的估计器去验证另一个估计器，属于循环论证。
答辩时被问"标签哪来的"，答"AI 看的"会很难解释。

---

## 二、录制要求

| 项目 | 要求 | 说明 |
|---|---|---|
| **时长** | 2~5 分钟一段 | 太短则 PERCLOS 的 30 秒滑动窗口填不满 |
| **开头** | **必须留 8~10 秒正视镜头、自然睁眼的清醒片段** | 用于个性化标定。缺这段会回退通用阈值，准确率明显下降 |
| 状态覆盖 | 清醒 → 轻度困倦 → 明显疲劳 | 尽量包含打哈欠、长闭眼（>1秒）、点头 |
| 格式 | MP4（H.264） | 兼容性最好。手机横拍即可 |
| 分辨率 | 720p 足够 | 更高分辨率只增加解码耗时，不提升关键点精度 |
| 距离 | 人脸宽度占画面 20%~80% | 太远关键点精度不足，太近会出框 |
| 光照 | 正面均匀照明 | 避免逆光、避免强光直射面部 |
| 角度 | 摄像头大致正对面部 | 大角度侧转会触发数据质量门控 |
| 眼镜 | 戴/不戴各录一段更好 | 可以对比眼镜反光对 EAR 的影响 |

### 录制时做一件事：随手记时间点

拿张纸记下"第 X 分 Y 秒开始觉得困"。事后标注会准得多——
凭记忆回看视频标注，很容易把边界记错。

### 建议的录制方案

如果时间有限，**一段 3 分钟的连续视频**就够用，比录多段短视频更好：
状态过渡自然，还能检验系统的等级跃迁与响应延迟。

如果想让实验更充分，再补几段特殊条件（每段 1~2 分钟即可）：

- 戴眼镜
- 光照较暗
- 侧脸 30° 左右
- 部分遮挡（手扶下巴等）

这些用于说明系统的适用边界，写进论文的"鲁棒性分析"。

## 三、操作步骤

1. 启动系统 → 随便跑一次检测 → 点「结束并生成报告」进入报告页
   （评测面板在报告页底部）
2. 找到「视频离线评测」→ 点「选择视频文件」导入
3. **先标注，再评测**：
   - 播放视频，到状态变化处暂停
   - 点「设为起点」→ 播到该状态结束 → 点「设为终点」
   - 点「标为正常」或「标为疲劳」
   - 重复直到覆盖整段视频
   - 调整坐姿、离开画面等无效片段标为「忽略」
4. 设置参数：
   - **采样步长**：默认 100ms。越小越精确但越慢，必须小于 400ms
   - **标定时长**：默认 8s，对应视频开头的清醒片段长度
   - **疲劳判定起始等级**：默认"轻度及以上"算作疲劳
5. 点「开始离线评测」，等进度条走完
6. 导出结果：JSON（完整数据）/ 逐点 CSV（画图用）/ 指标汇总 CSV（论文表格用）

> **顺序很重要**：必须先标注后评测。反过来会产生确认偏误——
> 先看到算法结果再标注，人会不自觉地把标签往算法输出上靠，
> 得出的准确率虚高且不可信。

标注结果可导出 JSON 保存。换参数重跑时导入即可，不必重新标。

## 四、怎么读结果

### 混淆矩阵

|  | 系统判为疲劳 | 系统判为正常 |
|---|---|---|
| **人工标注：疲劳** | TP（正确报警） | **FN（漏报）** |
| **人工标注：正常** | FP（误报） | TN（正确静默） |

**FN 是最需要关注的一格**：这段时间你确实疲劳，但系统没报警。
对安全相关系统而言，漏报一次的代价远高于误报一次。

### 核心指标

| 指标 | 含义 | 关注度 |
|---|---|---|
| **灵敏度** Sensitivity | 真实疲劳中被检出的比例 | ★★★ 首要 |
| **特异度** Specificity | 正常状态未被误报的比例 | ★★★ |
| **MCC** | Matthews 相关系数，−1~1，对不平衡稳健 | ★★★ |
| Youden's J | 灵敏度 + 特异度 − 1，0 等于随机猜测 | ★★ |
| 平衡准确率 | 灵敏度与特异度的平均 | ★★ |
| 准确率 Accuracy | 整体判对比例 | ★ **会骗人** |

### 为什么准确率会骗人

疲劳检测是**类别不平衡**问题：正常状态占绝大多数时间。
一个"永远输出正常"的系统在清醒为主的数据上准确率也能很高，但毫无用处。

系统自测中出现过一个典型实例：**准确率 52.6%，灵敏度 0%**——
看起来"一半以上判对了"，实际上一次疲劳都没检出来。
所以论文里必须同时报告灵敏度与特异度，不能只写准确率。

### 响应延迟

人工标注的疲劳区间开始后，系统需要多久才判为疲劳。
这个指标对疲劳检测特别重要——一个准确但滞后 60 秒的系统，
实际驾驶中可能已经来不及预警。

延迟主要来自 PERCLOS 的 30 秒滑动窗口累积，属方法固有特性，
论文中应如实报告并说明成因。

## 五、结果不理想怎么办

系统会自动给出诊断提示，常见情况：

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"人脸丢失率过高" | 取景、光照或遮挡问题 | 重新录制，确保面部完整入画、光照充足 |
| 提示"标定未成功" | 视频开头没有清醒正视片段 | 重录，开头留 8~10 秒正视镜头 |
| 灵敏度低（漏报多） | 阈值偏保守 | 用敏感性分析工具下调等级分界，或提高眼部指标权重 |
| 特异度低（误报多） | 阈值偏激进 | 上调等级分界 |
| 两者都低 | 标注与算法判据不一致 | 检查标注边界是否过于宽泛 |

调参后可以直接重跑（导入之前保存的标注），对比不同参数下的指标。
配合报告页的「参数敏感性分析」，能给出"为什么选这组参数"的完整论证链。

## 六、论文中的表述建议

**可以写的**：

- 在受控条件下、N 段视频、共 X 分钟有效标注数据上，
  系统灵敏度 XX%、特异度 XX%、MCC 0.XX
- 平均响应延迟 X.X 秒，主要来自 PERCLOS 窗口累积
- 参数敏感性分析显示默认阈值落在稳定平台区

**必须如实说明的局限**：

- 标签来源为被试本人主观自评，非 EEG 等生理金标准
- 被试数量与样本量有限，结论不能外推为普适准确率
- 仅验证受控条件下的可用性，未覆盖真实道路环境

诚实标注局限比夸大结论更容易通过答辩。评委关心的是你知不知道自己方法的边界。
